## 一、 日常活动体系与门槛依赖全景

在《梦幻西游手游》中，日常任务并非孤立存在，各活动之间存在严格的等级、前置顺序与**活跃度门槛**依赖关系：

| 任务名称 | 轮次 / 上限 | 活跃度产出 | 前置门槛与限制 | 推荐执行策略 |
| :--- | :--- | :--- | :--- | :--- |
| **师门任务** | 20 环 (前10高额) | **+20** | 等级 ≥ 20 级，无活跃度门槛 | **第一顺位**。全自动寻路交互、门派巡逻答题，提供每日初始 20 点活跃度。 |
| **宝图任务** | 10 次强盗 | **+10** | 等级 ≥ 25 级，无活跃度门槛 | **第二顺位**。店小二接取打图，击败强盗获取藏宝图道具，累计至 30 点活跃度。 |
| **秘境降妖** | 每日挑战次数（次数用完即拒绝，Toast 原文 `少侠今日已无挑战次数，明日再来吧`） | **+25**（按闯关进度累积，实测第6关=11/25） | 等级 ≥ 40 级；死亡 2 次后需仙玉续关 | **第三顺位**。次数用完后活动面板打"完成"胶囊且无参加按钮，**但实例仍可从 NPC 进入**：活动面板→活动地图(玩法地图)→秘境降妖"1-12关"→前往查看 → 寻路至东海湾 **云乐游 NPC** → 对话选"秘境降妖" → 秘境界面"继续挑战"；次数为 0 时被 Toast 拒绝（框架拦截词已覆盖）。未打满且参加按钮可见时正常派发闯关；仙玉弹窗绝不自动确认。 |
| **运镖任务** | 每日 3 次 | **+10** | **严格要求 活跃度 ≥ 50** | **第四顺位（强门控）**。若活跃度 < 50，点击会触发 Toast 报错并强制关闭面板；框架检测到活跃度不足时延迟补跑，达标后执行。 |
| **科举 / 三界奇缘** | 10~20 题 | **+10~20** | 每日定时开放 | **离线秒答 + 活跃度兜底**。本地 3854 条 SQLite 题库模糊匹配，15ms 内 100% 离线答题，零 Token 消耗；秘境拿不满时作为 50 门槛的备选活跃度来源。 |
| **活跃度宝箱** | 5 档阶段奖励 | 丰厚道具/金币 | 20 / 40 / 60 / 80 / 100 活跃度 | 每次打开活动面板时动态比对当前分值，自动领取已解锁宝箱并优先消除奖励弹窗。 |

## 二、 核心机制实现深度解析

### 1. 任务追踪栏优先寻路机制 (摒弃地图与 NPC 点击)

在传统外挂或低级脚本中，常试图计算大地图坐标或在主界面寻找 NPC 进行点击，这在大地图缩放、玩家遮挡或跨地图切线时极易失准。

**本项目最佳实践（借鉴自 `haungwanjun/mhxy_fz`）**：
- 梦幻客户端拥有强大的内置自动寻路系统，只要点击右上角的**任务追踪栏**（ROI: `x: 1050..1280, y: 150..320`），游戏客户端会自动跨地图寻路、切线并在到达目的地后自动弹出 NPC 对话框。
- `daily_handlers.py` 中的 `click_task_tracker`：
  1. 通过 RapidOCR 扫描右侧追踪栏区域；
  2. 根据当前任务类型模糊比对关键词（如“师门”、“宝图”、“贼王”、“强盗”、“运镖”）；
  3. 命中任务条目后，在条目热区内加入二维高斯偏置直接点击；
  4. 若未命中具体关键词，点击顶部首个任务槽位（`1145, 210`）作为保底；
  5. 随后由 `classify_screen` 自动监听并切换到 `walking`（自动寻路中）或 `dialog_open` 状态。

```python
def click_task_tracker(ctx: PipelineContext, act: NodeAction) -> None:
    """点击右上方任务追踪栏驱动客户端原生自动寻路。"""
    items = ctx.variables.get("_last_frame_items") or []
    curr_task = ctx.variables.get("current_task_name", "")

    task_kws = {
        "师门任务": ["师门"],
        "宝图任务": ["宝图", "贼王", "强盗"],
        "运镖": ["运镖", "押镖"],
    }
    # 查找任务追踪项并点击
    tracker_item = _find(items, lambda it: any(kw in it.text for kw in task_kws.get(curr_task, [])) 
                         and 1050 < it.center[0] < 1280 and 150 < it.center[1] < 320)
    if tracker_item:
        tx, ty = _center(tracker_item)
        _click(ctx, tx, ty)
    else:
        _click(ctx, 1145, 210)  # 默认顶部槽位保底
    time.sleep(2.5)
```

### 2. 50 活跃度门槛自愈延迟补跑与宝箱动态领取

在日常流水线执行过程中，若角色刚做完师门（20）和宝图（10），当前活跃度仅为 30 点。此时若点击运镖，游戏会弹出 Toast 报错：`"运镖需要活跃度达到50点你的活跃度不够，快去提升活跃度吧。"`，并自动关闭活动面板，导致脚本进入打开面板-点击运镖-关闭面板的死循环。

**工程实现与闭环方案**：
1. **活跃度分值提取 (`_extract_huoyue`)**：
   在打开活动面板时，轻量 OCR 锚定底部活跃度进度条（`y: 605..655, x: 350..1150`），精确解析当前数值并存入上下文 `ctx.variables["current_huoyue"]`。
2. **前置门槛延迟补跑（2026-09-25 升级）**：
   若活动为“运镖”且 `current_huoyue < 50`，设置 `escort_deferred=True` 并**保持运镖未完成**（不再永久标记 completed），继续派发队列后续任务；每次面板重开时以最新活跃度重新校验，达标即自动补跑（运镖 3 趟由面板次数计数器自然闭环）。默认队列顺序调整为 `["师门任务", "宝图任务", "秘境降妖", "三界奇缘", "运镖"]`，先做高活跃度日常再触达运镖门槛。终局决策（其余日常全部完成后）：活跃度已达标但运镖卡片漏解析（面板滚动/OCR 漏检）→ 按未滚动面板固定行坐标 `ESCORT_JOIN (1077, 148)` 兜底点参加；仍 `< 50` → 明确告警当日活跃度缺口（`缺口 {50-current_huoyue} 点`）并标记完成，避免死循环。
3. **浮动 Toast 拦截**：
   在 `classify_screen` 中实时拦截 `"活跃度不够"` / `"需要活跃度达到50点"`（标记运镖当日不可解锁）与 `"挑战次数已用完"`（置 `mijing_quota_exhausted=True`，秘境当日收尾）两类门槛语义，重置面板标记避免重复死磕。
4. **秘境活跃度达标判据与仙玉安全（2026-09-25 实机修正）**：
   秘境降妖的 +25 活跃度按闯关进度累积（实机实测：今日进度第6关 = 活跃 11/25），每日挑战次数用完即打"完成"胶囊。**实机结论：面板"完成"态 ≠ 不能打**——活动面板无参加按钮、详情弹窗纯展示，但实例可从实际地图 NPC 进入，确定性入口链路（全固定坐标）：
   `活动面板 → 活动地图 (210,661) → 玩法地图"秘境降妖 1-12关"框 (310,537) → 前往查看 (800,497) → 寻路至东海湾 云乐游 NPC → 对话选项"秘境降妖" (1088,264，注意位置偏高，对话扫描 y 带已放宽至 200..680) → 秘境界面"继续挑战" (1037,622)`。
   次数用完时点击被 Toast 拒绝（`少侠今日已无挑战次数，明日再来吧`，拦截词已覆盖 → `mijing_quota_exhausted` 如实收尾）；进度跨日保存（今日第6关/解锁至第9关）。框架四重机制：
   - **完成判据与活跃计数**：`_parse_activity_panel` 以参加按钮同位的"完成"胶囊为游戏权威完成信号（兼容 已完成/次数打满），同时解析卡片 `活跃X/Y` 计数；秘境被标完成但 `X<Y` 时打出 WARNING `pill-marked 完成 but 活跃 11/25`，缺口如实上报不掩盖。
   - **面板滚动补扫**：师门/宝图/秘境都在面板首屏之下——队列任务不在可见卡片中时先上滑滚动（每周期至多 2 次）下一 tick 再决策，杜绝"看不见即按完成推断"；滚动态下固定行兜底坐标失效，运镖兜底先滚回顶部再点（一次性 `escort_scrollback_done` 标志防抖）。
   - **活跃度像素兜底**：进度条上的分数气泡为艺术字，RapidOCR 完全读不到（实测气泡"41"从不出现在 OCR 输出）——`_extract_huoyue_from_frame` 按绿色填充宽度换算（条轨 x 326..1067 = 0..100，以 20/40/60/80/100活跃 刻度标定），OCR 失败时精确恢复分值。
   - **仙玉/退出双安全红线**：任何含 `"仙玉"` 字样的弹窗（死亡复活/继续挑战）绝不自动确认——`classify_screen` 将其从 `deposit_open`/`use_item_open` 确认分类中排除并路由 `dismiss_popups`，后者优先点 `取消/离开/退出` 安全退出并置 `mijing_blocked=True` 阻断当日秘境派发；双击返回触发的退出游戏确认（`少侠确定离开游戏吗`，确定=退出客户端）同样永不确认、强制取消（OCR 空格归一化匹配"取 消"）。
5. **三界奇缘活跃度兜底**：
   秘境拿不满（次数用完/战败受挫）时，默认队列中的三界奇缘（+10~20 活跃度，离线答题引擎秒答）在运镖之前派发，用于补足 50 门槛；答题每日定时开放，未开放时卡片缺席自动跳过。
5. **活跃度读数以像素为主源 + 押镖实机闭环（2026-09-25 实机联调）**：
   - **读数优先级反转**：实跑发现 OCR 会把进度条气泡"61"部分误读成"6"——非零误读会绕过像素兜底、导致运镖被误判放弃。`handle_activity_panel` 改为**像素测量为主源**（`_extract_huoyue_from_frame`），OCR 仅在无帧/无条时兜底。
   - **押镖赶路界面识别**：押镖自动赶路展示世界地图（"距离运镖完成：N秒"倒计时 + 彩色地名标签），会被行分组拼成假题干触发 quiz_answer 盲点。新增 `escort_traveling` 分类（quiz 排除 + `has_active_work` 纳入 → 流水线安静等待），并新增 `test_quiz_done_route_requires_quiz_context` 等回归。
   - **押镖 3 趟实机闭环实证**：派发（活跃度 62≥50）→ NPC 对话"押送普通镖银"(1086,400) → 押金"确定"(747,420) → 世界地图赶路（倒计时自走）→ 到站自动交付，3 趟全部完成，面板实证 **运镖 次数3/3 活跃9/9**，活跃度 61→71，宝箱领取 20/40/60 档，72 tick 收敛 `daily_finish`。
6. **宝箱动态领取与弹窗消除**：
   根据提取到的活跃度，自动点击对应宝箱图标坐标（实机校准：图标在进度条上方 y≈570，其下 y≈666 是文字标签不可点）：
   - 20 活跃宝箱：`(457, 570)`
   - 40 活跃宝箱：`(609, 570)`
   - 60 活跃宝箱：`(760, 570)`
   - 80 活跃宝箱：`(911, 570)`
   - 100 活跃宝箱：`(1063, 570)`
   在领取后往往会弹出“获得九转金丹/宝箱物品”的确认弹窗。在 `daily_dailies.json` 中配置 `popup_open -> dismiss_popup` 的优先级高于 `all_dailies_done -> daily_finish`，确保奖励弹窗被点击关闭后再终结流程。

## 三、 底层多门派战斗策略可扩展架构 (Extensible Combat Strategy Matrix)

战斗是回合制 MMORPG 自动化中的底层生命线。针对项目未来将支持多门派角色协同运转（魔王寨、方寸山、普陀山、化生寺、龙宫等），框架将战斗决策完全抽象为解耦的**门派策略注册表（`SectCombatRegistry`）**与**决策引擎（`combat_strategy.py`）**，彻底避免在流程中硬编码特定门派。

### 3. 门派自愈自适应机制（Zero-Config Auto Detection）

1. **显式传参优先**：若 `ctx.variables["sect"]` 或账号配置已指定门派，决策引擎精准装载该门派策略类。
2. **视觉特征自适应识别**：若未预先配置门派，`SectCombatRegistry.detect_sect_from_items` 扫描当前屏幕及技能轮盘上展示的技能关键词。例如，当检测到界面出现【飞砂走石】时，引擎自动将当前上下文自适应绑定为【魔王寨】；检测到【五雷咒】时自适应绑定为【方寸山】。
3. **安全缺省降级**：若未识别到任何门派特征，安全降级至默认物理输出策略（月宫）。

### 4. 召唤兽（宠物）行动分发标准

- **物理攻宠 (`attack`)**：直接点击【攻击】按键，优先锁定敌方当前血量最低目标或单体主怪。
- **法术法宠 (`magic`)**：点击【法术】按键，优先释放群体法术（如【泰山压顶】、【奔雷咒】、【水漫金山】、【地狱烈火】）。
- **血宠/配速 (`blood`)**：执行【防御】保全战力，或根据战局执行喂药拉人。

### 5. 首回合自动战斗与防封优化

- 首回合根据策略精准下达门派技能与集火指令后，系统进入动画等待阶段。
- 在后续回合中，若界面右下角出现高亮“自动”按键，脚本自动点击激活游戏内置自动战斗。
- **防封关键**：进入自动战斗后，脚本暂停任何非必要点击，进入休眠轮询观察状态，彻底杜绝在战斗动画期间向客户端发送固定坐标机械空点，规避网易易盾的行为动力学风控。

## 六、 本地离线答题引擎：科举/三界奇缘零 Token 作答 (2026-09-25)

### 1. 数据与引擎血缘（上游直接收割，不造轮子）
题库四源快照位于 `plugins/mhxy_mobile/custom/data/quiz_sources/`，合计 4263 条真题，按归一化题干去重后落库 **3854 条**：

| 来源仓库 | 格式 | 条数 | 特点 |
|---|---|---|---|
| `0xn0ne/MHXYExamAssistant` | SQLite | 838 | 手游真题（question/answer） |
| `gitlihang/Maa_MHXY_MG` | tiku.txt | 393 | 手游多合法答案 `{题干: [答案...]}` |
| `kslf-interest/mhxy_exam_answer` | JS 数组 | 446 | 手游 |
| `PilyTang/XYQQuiz` | JSON | 2586 | PC 科举 |

引擎：`plugins/mhxy_mobile/custom/quiz_solver.py`（`QuizBank` + `QuizSolver` + `QuizDecision`），SQLite 表 `questions(q_norm UNIQUE, q_raw, answer, answers_json, category, source)`。

### 2. 匹配与作答策略
1. NFKC 归一化（全半角/标点/空白剥离）→ 归一化题干 UNIQUE 索引精确命中；
2. RapidFuzz `fuzz.ratio` ≥ **0.82** 模糊命中；70~82 为低置信带，仅告警不自动作答（沿用上游 Maa 80 分策略）；
3. 多合法答案逐一对映屏幕选项（`token_set_ratio`，阈值 0.55），综合置信 = 0.55×题干分 + 0.45×选项分（上限 0.98）；
4. 未命中：点第一选项（上游策略）；`quiz_vlm_enabled=True` 时优先 Tier-2 VLM（`MHXYVLMSolver.solve_exam`），日常保持零 Token。

性能实测（3854 条题库）：精确命中 0.0~2.1ms、最坏全表扫描（miss）2.9ms，均在 15ms 预算内；512 条查询缓存应对同屏多 tick。

### 3. 屏幕接入（借上游 Maa `reco_sjqy` 同构常量）
- 题目 ROI `[447,40,673,94]`、选项 ROI `[439,218,678,212]`（1280x720）；
- 20px 行分组组题、`第n题`/`（n/m）` 标记清洗、OCR 误读替换表（味→昧/邮→邺/尺→尸/频→濒/铜→锢）；
- `classify_screen` 输出 `quiz_open`；`daily_dailies.json` 分支 `quiz_open -> quiz_answer`（优先级仅次战斗、先于弹窗处理，防误关答题界面）；**主城 HUD 一票否决**（2026-09-25 实机修正）：顶部栏 `指引/排行/挂机/社群/直播录像` 按钮是世界界面独有元素，真答题界面绝不出现——存在任一即强制 `quiz_open=False`，否则拥挤的主城文字（玩家名 + 活动横幅）会被行分组拼成假题干并在选项 ROI 盲点"首选项"（实机事故复盘：随机点击挪动了角色、误触 NPC）；
- `handle_quiz`：答题完成页按返回键并登记 `三界奇缘` 完成；结果反馈弹窗（回答正确/答错了）自动点 确定/继续/下一题。
