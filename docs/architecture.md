> **版本**: 1.2.0 (Milestone 7)  
> **更新日期**: 2026-09-24  
> **核心规范**: 确定性零 Token 本地日常脚本与大模型能力边界分层设计

## 一、 架构愿景与双层防御哲学 (Two-Tier Architectural Principle)

在《梦幻西游手游》等重度 MMORPG 自动化和多开搬砖场景中，成本控制、执行时延与账号安全构成了核心工程挑战。传统的纯大模型/多模态方案存在 API 费用高昂、网络延迟高（1~3s）、显存溢出及幻觉误触等致命问题；而传统的硬编码像素脚本又极易失配崩溃。

因此，本项目确立了**“本地确定性脚本流水线 + 高价值大模型兜底”的双层防御架构哲学**：

```
┌────────────────────────────────────────────────────────────────────────┐
│                        game-auto-framework 中台调度                    │
└───────────────────────────────────┬────────────────────────────────────┘
                                    │
         ┌──────────────────────────┴──────────────────────────┐
         ▼                                                     ▼
┌─────────────────────────────────┐   ┌─────────────────────────────────┐
│     第一层：本地确定性流水线     │   │      第二层：储备大模型防御层   │
│   (Zero-Token Local Pipeline)   │   │     (Reserved VLM / LLM Tier)   │
├─────────────────────────────────┤   ├─────────────────────────────────┤
│• 适用场景：100% 涵盖所有高频重复 │   │• 适用场景：极低频、高价值场景   │
│  日常（师门、宝图、运镖、秘境、 │   │  - 节日未知新活动玩法探索       │
│  科举答题、工坊挖宝、商会变现） │   │  - 新型复杂防挂机验证码化解     │
│• 核心技术：                     │   │    （如未收录的文字点选/旋转图） │
│  - 声明式 DAG 状态机流水线      │   │  - 本地题库未收录的长尾冷门问答 │
│  - RapidOCR ONNX + RapidFuzz    │• 核心技术：                     │
│  - OpenCV 金字塔多尺度模板匹配  │  - OpenAI / Zhipu 视觉多模态 API│
│  - 局部区域差分哈希 (dHash)     │  - Zero-Shot 屏幕目标意图推理   │
│  - 本地离线 20,000+ SQLite 题库 │• 成本与时延：                   │
│• 成本与时延：                   │  - 仅占系统总调用频次的 < 0.1%  │
│  - 0 Token 成本，30~300ms 响应  │  - 1.5~3.0s 响应，即时告警接管  │
└─────────────────────────────────┘   └─────────────────────────────────┘
```

### 核心铁律
1. **日常活动绝对零 Token 依赖**：任何师门任务、打图挖宝、押镖、秘境降妖等每日重复流转，严禁调用大模型接口，全部由本地确定性 DAG 节点与轻量算子闭环完成。
2. **任务追踪栏优先寻路**：寻路与 NPC 交互坚决杜绝依赖世界地图像素坐标点击，统一通过识别并点击右上方任务追踪栏（`click_task_tracker`），触发游戏原生自动寻路与跨地图切线。

## 三、 现代五层解耦系统架构 (Five-Layer Decoupled Architecture)

```
┌────────────────────────────────────────────────────────────────────────┐
│                        Layer 5: 控制平面 (Control Plane)               │
│    FastAPI REST API / WebSocket 实时视频流 / SPA Web 控制台 / 原生 MCP │
└───────────────────────────────────┬────────────────────────────────────┘
                                    │
┌───────────────────────────────────▼────────────────────────────────────┐
│                  Layer 4: 集群与风控调度 (Cluster & Risk)              │
│    InstancePool (细粒度双锁) / 独享代理池 (1:1家宽网关) / 账号矩阵作息 │
└───────────────────────────────────┬────────────────────────────────────┘
                                    │
┌───────────────────────────────────▼────────────────────────────────────┐
│                 Layer 3: 游戏插件包 (Game Plugin Subsystem)            │
│    mhxy_mobile (梦手插件) / yys_mobile (阴阳师插件) / 动态插件注册表    │
│    (Pipelines JSON / Coordinates / Local QuizSolver / Daily Handlers)  │
└───────────────────────────────────┬────────────────────────────────────┘
                                    │
┌───────────────────────────────────▼────────────────────────────────────┐
│               Layer 2: 状态机与流水线调度 (Scheduler & Pipeline)        │
│    增强型 DAG 引擎 (动态分支/变量流) / 三级逃生链 / 任务链与安全熔断   │
└───────────────────────────────────┬────────────────────────────────────┘
                                    │
┌───────────────────────────────────▼────────────────────────────────────┐
│                 Layer 1: 核心引擎底座 (Core Engine Subsystem)          │
│    WGC/DXGI/ADB/Virtual 截屏 / OpenCV 模板 / RapidOCR / 三阶贝塞尔拟人 │
└────────────────────────────────────────────────────────────────────────┘
```

### 1. Layer 1: 核心引擎底座 (`core/`)
- **捕获层 (`core/capture/`)**：统一多后端截屏抽象，支持 Windows WGC/DXGI、Linux/Mac ADB 截图流以及生产无头虚拟画布引擎（`VirtualDevice`）。
- **视觉层 (`core/cv/`)**：
  - 快速 dHash 差分哈希计算（<3ms），过滤无变化帧；
  - 多尺度金字塔模板匹配（0.85~1.15x），解决不同模拟器分辨率微小缩放；
  - 战斗金色高光 HSV 掩模毫秒级脱战检测。
- **文字识别层 (`core/ocr/`)**：RapidOCR ONNX 离线推理 + RapidFuzz 模糊拼写纠错，支持文本相对屏幕中心反向定位。
- **拟人输入层 (`core/input/`)**：
  - 2D 高斯随机偏移（$\sigma=3\sim 6$px），消除几何中心连点；
  - 三阶贝塞尔曲线（Bézier Curve），实现 Ease-in 加速、巡航与 Ease-out 缓冲；
  - 55~120ms 泊松分布按压驻留时间与指腹微漂移（Micro-Drift）。

### 2. Layer 2: 状态机与调度引擎 (`scheduler/`)
- **增强型 DAG 引擎 (`scheduler/dag.py`)**：基于声明式 JSON 配置，支持动态分支跳转（`branches`）、全局变量跨节点传递与条件评估。
- **看门狗自愈逃生机制 (`scheduler/escape.py`)**：监测任务超时，触发三级阶梯脱困（1级点空白/关弹窗，2级点击返回主界面，3级重启重连）。
- **日常任务链与熔断 (`scheduler/routine.py`)**：串联多个日常活动流水线，监控收益阈值与异常熔断保护。

### 3. Layer 3: 游戏插件扩展包 (`plugins/`)
- 业务逻辑与核心引擎彻底解耦，框架自身不含任何游戏硬编码。
- 每个游戏为独立目录，包含 `manifest.json`、`config/`（分辨率与坐标）、`pipelines/`（DAG JSON）与 `custom/`（本地定制算子与题库）。

### 4. Layer 4: 集群与风控防护 (`cluster/`)
- **`InstancePool`**：多开实例生命周期管理，采用状态读写锁（`_state_lock`）与执行互斥锁（`_exec_lock`）细粒度双锁隔离，杜绝死锁与并发争抢。
- **`ProxyManager`**：独享代理池管理，通过 Cloudflare 隧道桥接用户真实住宅家宽出口（如上海移动家宽 `183.193.161.62`），严格执行**“单住宅 IP ≤ 5 角色（1个队伍）”**的防封红线。
- **`AccountMatrix`**：账号资产与作息管理，引入模拟人类生理疲劳曲线与上下线时间抖动。

### 5. Layer 5: 控制平面与远程中枢 (`server/`)
- **FastAPI 微服务**：提供集群状态、实例管理、任务触发、遥测统计等标准 REST 接口。
- **动态 Web Dashboard**：嵌入式现代化暗色控制台，实时展示集群状态、动态游戏画布渲染、拟人点击涟漪与时序指标大盘。
- **原生 MCP Server (`server/mcp.py`)**：暴露标准 Model Context Protocol 工具，允许 AI Agent 进行自动化巡检与高阶调试。

## 四、 核心业务流水线：日常活动门槛与自愈机制

在《梦幻西游手游》日常流水线中，活动之间存在严格的前置数值约束：

```
[每日初始状态]
      │
      ▼
┌──────────────┐
│   师门任务   │  +20 活跃度 ──► 累计活跃度: 20 ──► 解锁并领取 20 活跃度宝箱
└──────┬───────┘
       │
       ▼
┌──────────────┐
│   宝图任务   │  +10 活跃度 ──► 累计活跃度: 30 ──► (30 < 50, 运镖仍被锁定!)
└──────┬───────┘
       │
       ▼
┌──────────────┐
│   秘境降妖   │  +25 活跃度(需当日打满 次数10/10) ──► 累计活跃度: 55 ──► 解锁并领取 40 活跃度宝箱
└──────┬───────┘                                    (55 >= 50, 满足运镖门槛!)
       │
       ▼
┌──────────────┐
│   三界奇缘   │  +10~20 活跃度(定时开放,兜底源) ──► 秘境拿不满时补足 50 门槛
└──────┬───────┘
       │
       ▼
┌──────────────┐
│   运镖任务   │  +10 活跃度 ──► 累计活跃度: 65 ──► 解锁并领取 60 活跃度宝箱
└──────┬───────┘
       │
       ▼
┌──────────────┐
│ 挖宝图/答题  │  +20~35 活跃度 ──► 累计活跃度: 85~100 ──► 解锁 80/100 活跃度宝箱
└──────┬───────┘
       │
       ▼
┌──────────────┐
│ daily_finish │  消除所有领奖弹窗 -> 关闭活动面板 -> 完成脱战驻留
└──────────────┘
```

### 1. 运镖 50 活跃度门控算法
运镖任务需要扣除 50 活跃度入场券，若活跃度不足点击运镖，游戏会弹出 Toast `"运镖需要活跃度达到50点你的活跃度不够，快去提升活跃度吧。"` 并强行关闭活动面板。
- **解决机制**：在 `handle_activity_panel` 中，优先调用 `_extract_huoyue` 提取面板底部数字。若 `current_huoyue < 50`，自动将运镖移入跳过列表，优先调度秘境等其他产出活跃度任务；同时在 `classify_screen` 中识别 Toast，避免陷入重试死循环。

### 2. 宝箱领取与弹窗消除流水线
- 活跃度每达到一个档位（20/40/60/80/100），触发动态宝箱点击。
- 在 `daily_dailies.json` 中，分支优先级设定为：`popup_open -> dismiss_popup` 高于 `all_dailies_done -> daily_finish`。确保宝箱开启后的物品奖励确认弹窗被彻底关闭后，再结束日常流程。

## 六、 安全与防苦行合规红线 (Anti-Detection Compliance)

1. **零内存/协议侵入**：框架不使用任何 `ReadProcessMemory` / `WriteProcessMemory`、DLL 注入或 TCP 协议篡改，100% 依托外部图像捕获与 ADB/模拟器硬件级触控。
2. **拟人化物理驱动**：严格执行三阶贝塞尔滑动轨迹与泊松驻留时间，消除机械直线与零延迟连点特征。
3. **网络拓扑隔离**：生产集群必须通过上海移动住宅家宽节点（`183.193.161.62`）通信，遵守单 IP 负载 ≤ 5 角色红线，严禁直接使用数据中心公网 IP。
4. **边缘安全避让**：触控热区严格避开系统设置、好友通讯录、充值福利等高危弹窗边缘。
